# be-a.network — technical context

Primer for the browser version of the Network Learning Toolkit. Covers the Rust
engine in `engine/` and the TypeScript app in `web/`. Version **0.2.0**.

---

## 1. What this is

A browser port of three WPF/C# teaching apps that remain in the repo root as the
reference implementation and are **not modified**:

| Exercise | Teaches |
| --- | --- |
| BeASwitch | MAC learning, VLAN tagging, layer-2 forwarding decisions |
| BeARouter | Longest-prefix-match routing, reading a routing table |
| IP Quiz | Subnetting, netmask conversion, IPv6 abbreviation, EUI-64 |

Published as a static site at **be-a.network**. No backend, no runtime network
calls of any kind, installable as a PWA, works offline after first load.

Deliberately dropped from the desktop original: success certificates, RSA/AES
certificate encryption, DNS-TXT service discovery and HTTP submission, and the
`SuccessCertificateVerficiationTool`. An exam now ends in a local summary screen.

## 3. Architectural rules

1. **All simulation logic lives in Rust.** TypeScript only renders and collects
   input. No networking maths in TS.
2. **Expected answers never cross the wasm boundary before scoring.** `submit()`
   takes the student's answer and returns a verdict; the solution appears in the
   snapshot only afterwards. This is a functional requirement, not a nicety —
   see the `RouteDto.port` note in §5.
3. **Core crates have zero dependencies.** Only `wasm-api` pulls in crates.
4. **The UI is stateless between renders.** Each view holds a `snapshot` from the
   engine and re-renders from it; there is no separate UI state model.
5. **No framework.** Plain DOM via the `el()` / `svg()` helpers in `shared/dom.ts`.

## 4. The Rust engine

### Workspace

`engine/Cargo.toml` sets the shared version and this release profile:

```toml
opt-level = "z", lto = true, codegen-units = 1
panic = "abort", strip = "symbols", overflow-checks = false
```

Output: ~191 KB raw, ~81 KB gzipped.

### `net-core` (no dependencies)

- `rng.rs` — xoshiro256++ seeded through SplitMix64, Lemire debiased range
  reduction, Fisher-Yates `shuffle`. **Written by hand on purpose**: it removes
  the `rand`/`getrandom` dependency and its wasm JS shim, and makes every game
  reproducible from a seed. The host supplies the seed from
  `crypto.getRandomValues`.
- `mac.rs` — `MacAddress`, parses `:`/`-` separators, uppercase display,
  `random()` clears the multicast bit so generated source MACs are valid.
- `v4.rs` — `SubnetV4 { address, mask }`, mask/dotted conversion (rejecting
  non-contiguous masks), network/broadcast/host-min/host-max, `matches`,
  `apply_mask_to`, `split`, `random_ipv4_subnet`, `random_public_ipv4_subnet`.
- `v6.rs` — `SubnetV6`, `expand`, `abbreviate`, `alternative_abbreviation`,
  `eui64`, `number_of_subnets`, `random_ipv6_subnet`.
- `score.rs` — `UserScore` (+50 correct, −25 wrong, floored at 0) and
  `Goal`/`GoalStatus`, ported from `BeAToolsLibrary/Goal.cs`.

### `switch-engine`

`engine.rs` holds the forwarding truth table, ported literally from
`BeASwitch/SwitchEngine.cs`:

- VLAN resolution: an untagged frame takes `port.untagged.first()`; if the port
  has no untagged VLAN it is **discarded**. A tagged frame must have its tag in
  `port.tagged`, otherwise **discarded**.
- The source MAC is learned into the per-VLAN table on every accepted frame.
- Destination known **and on the ingress port** → `Discard` (a switch never sends
  a frame back where it came from).
- Destination known → `Unicast`. Unknown → `Broadcast`.
- `expected_decisions()` builds the answer key: broadcast selects every member
  port **except the ingress port**; unicast selects only the destination port;
  discard selects nothing.

`game.rs` orchestrates rounds: 6 ports, 12 stations, VLAN randomisation into
access ports plus one trunk and one hybrid port, scoring and goal tracking.

Stations are labelled `A`..`L` rather than given real MACs — a deliberate
pedagogical choice inherited from the original.

### `router-engine`

`routing.rs`:

- `RoutingTable::route_for` — longest prefix wins, the first row wins a tie.
- A destination equal to a route's **network address** or **broadcast address**
  is rejected for that route (`MatchOutcome::TargetIsNetworkAddress` /
  `TargetIsBroadcast`). Inherited from `RoutingTable.cs`.
- `match_all` returns a `RouteMatch` per row with the masked destination and the
  route's network, which drives the Explain view.
- Table is sorted `(mask asc, network asc)`, so least specific is shown first.

`game.rs` builds 5 interfaces with non-overlapping subnets, connected routes,
remote routes via a neighbour inside a connected subnet, a deliberately
overlapping supernet so longest-prefix-match actually decides, and a default
route. An answer is correct iff the selected set is exactly the expected port.

### `quiz-engine`

- `question.rs` — `Question` carries `subject`, `subject2`, `answer`, `options`
  and a `Matcher` describing how to compare a typed answer: `Exact`, `Ipv4`,
  `Integer` (tolerates `'`, `,`, `.`, spaces), `Cidr` (compares network+mask),
  `Ipv6Expanded`, `Ipv6Abbreviated` (rejects an uncompressed spelling).
- `types.rs` — `REGISTRY`, a **static** slice of 12 generators with a `frequency`
  weight. The original discovered these by scanning assemblies with reflection,
  which cannot work in wasm.
- `quiz.rs` — weighted selection that avoids asking the same kind twice in a row,
  category filters, scoring, goal.

Kinds: `networkAddress`, `broadcast`, `numberOfHosts`, `splitSubnetSecond` (×2),
`splitSubnetThird` (×2), `cidrToDotted`, `dottedToCidr`, `abbreviateIpv6`,
`expandIpv6`, `ipv6Prefix`, `eui64`, `numberOfIpv6Subnets`.

## 5. The wasm boundary (`wasm-api`)

Three exported classes — `SwitchGame`, `RouterGame`, `QuizSession` — each with
`snapshot()`, a "next" method, `submit()`, `restart()`, `free()`. Every method
returns a full snapshot, so the UI never patches state incrementally.

Dependencies: `wasm-bindgen` 0.2, `serde` 1, `serde-wasm-bindgen` 0.6.

Two non-obvious details, both load-bearing:

- **`serialize_missing_as_null(true)`** in `dto.rs::to_js`. By default
  serde-wasm-bindgen maps Rust `None` to `undefined`, not `null`, which silently
  breaks every `x === null` check in TypeScript. All three snapshot builders go
  through this helper.
- **`RouteDto.port` is `Option<usize>`**, populated only for on-link routes. For
  a gateway route the egress interface *is* the answer, so exposing it would let
  a student read it out of the JS heap.

`SessionOptions.seed` arrives as an `f64` and is turned into `u64` with
`to_bits()`, so the whole 64-bit pattern is used.

## 6. The web app

- **Vite 5**, `base: './'` so the same artifact works from a domain root, a
  GitHub Pages sub-path or `file://`.
- `__APP_VERSION__` is injected from `package.json` via `define` and declared in
  `src/globals.d.ts`. `package.json` is the single source of truth for the
  footer version. Note `web/package.json` and `engine/Cargo.toml` are bumped
  together; use `npm version` so the lockfile stays in sync (`npm ci` hard-fails
  on drift).
- **Routing**: hash based — `#/`, `#/switch`, `#/router`, `#/quiz`.
- **i18n**: `de`, `en`, `pt-BR`, `es-419`. BCP 47 tags are used because they also
  feed `Intl` and `<html lang>`. `LOCALE_LABELS` maps them to the short button
  labels `DE/EN/BR/ES`. Detection walks `navigator.languages` by prefix.
  All storage access is wrapped in `try`/`catch` (Safari private mode throws).
- **Storage** (`shared/storage.ts`): `bea.settings.v2` (per-exercise settings),
  `bea.progress.v1`, `bea.exams.v1` (passed exams, newest first, capped at 50),
  `bea.locale`. Settings are normalised field by field, so an unknown or stale
  blob degrades to defaults rather than throwing.
- **Colour modes** (`shared/theme.ts`, `extras/colourModes.ts`): `system` plus
  twelve named palettes, written onto `<html>` as `data-theme`. The names stay
  English in every locale and live in `THEME_LABELS` rather than the catalogs,
  for the same reason as `LOCALE_LABELS`: they are names, not interface copy. The palettes are
  pure token overrides at the end of `tokens.css`; anything a mode leaves out
  is inherited from the default. Two details there are load-bearing: the
  selector is the bare `[data-theme='…']` rather than `:root[data-theme='…']`,
  so a preview card can repaint its own subtree and show the real palette — and
  because that ties with `:root` on specificity, the mode blocks must stay
  *after* the `prefers-color-scheme: light` block, which is what makes them
  win. The default palette answers to `[data-theme='system']` as well, so the
  System card previews the true default rather than whatever is active.
- **Header controls** (`shared/displayControls.ts`): motion and text size ride
  in every header, next to *Back to menu*, because both are about the room the
  app is being shown in. The language picker stays on the menu. The group
  re-renders only itself: motion is re-read by each animation and the text size
  is carried by CSS, so no view needs to redraw.
- **Text size** (`shared/textSize.ts`): the `Aa` button cycles 100 /
  120 / 145 %, written as a percentage onto `<html>` so every `rem` in the
  stylesheets follows it, including `.app`'s `max-width` — the two-column
  layouts widen with the text instead of squeezing the tables. Percent rather
  than pixels keeps a reader's own browser default as their 100 %. The SVG
  topologies are drawn in their own user units and do not follow it.
  `<html>` also carries a `text-<level>` class, for the rules a `rem` cannot
  express: at `text-xlarge` the switch and router layouts collapse to one
  column so the topology spans the full width, with `max-height: 80vh` on the
  canvas so a 16:9 projector does not end up scrolling.
- **PWA**: `public/sw.js` is served from the site root so its scope covers the
  whole app; registered as `new URL('sw.js', document.baseURI)`. Cache-first,
  with navigations falling back to the cached shell.

### Configured links (`shared/config.ts`)

The extra features window (footer → *Extra features*) builds a link that opens
the site already set up, for handing to a class:

```
?tools=switch,quiz&lock=1&switch=exam:16/20,novlan&quiz=practice,ipv6
?only=router&lang=de&router=exam:8/10
```

| Parameter | Meaning |
| --- | --- |
| `tools` | exercises the menu offers; their deep links are the only ones honoured |
| `only` | open that exercise straight away, no menu and no back button |
| `lock` | hide the option editors; the card shows the fixed mode instead |
| `lang` | force a locale for this visit, **without** persisting it |
| `motion` | `0` forces reduced motion |
| `switch` / `router` / `quiz` | `exam:C/T` \| `practice`, plus `vlan`/`novlan` and `ipv4`/`ipv6` |

Four things about it are deliberate:

1. **The query string, not the hash.** The hash is the router; `#/switch`
   changes while the configuration must not.
2. **Readable parameters rather than one base64 blob**, so a teacher can read
   and edit a link. `buildQuery` therefore serialises by hand —
   `URLSearchParams.toString()` would percent-encode the `,` `:` `/`
   separators. Parsing still goes through `URLSearchParams`, which accepts
   both spellings.
3. **A link only ever suggests values.** `activeSettings()` lays them over the
   stored settings; `persistSettings(next, scope)` records that the learner
   edited something and stops the link speaking for that scope. The scope is
   split into `exercises` and `motion` because the motion toggle stays
   available under `lock`, and using it must not discard the exam setup.
4. **The builder spells out the options of every offered exercise**, even at
   their defaults, so a link never inherits whatever the learner had stored.

`lock` hides controls; it does not enforce anything, in the same spirit as
§10's note on the wasm engine. The link itself is plainly editable.

Every parameter is normalised or dropped on the way in, exactly as the stored
settings blob is, so a truncated or hand-mangled link degrades to defaults
rather than throwing.

### SVG topologies and animation

Both exercise views draw an inline SVG and animate it with the Web Animations
API. Two rules matter:

1. **Tokens are declarative.** The frame and the packet are rendered by
   `renderTopology` at a *resting position* (parked on the switch, or on each
   port it was forwarded to). Animations move existing nodes; they never create
   or destroy them. Anything created only inside an animation is lost on the
   next re-render and starts life at the SVG origin.
2. **CSS `transform` replaces the SVG `transform` attribute.** They are the same
   property. `shared/animate.ts` exposes `baseTransform(node)`, and every
   transform keyframe in `pulse()` and `shake()` is prefixed with it. Only
   `travel()` uses `fill: 'forwards'`; everything else must fall back to the
   attribute. `.port` and `.interface` also set `transform-box: fill-box` so
   `scale()` pivots on the element rather than the canvas centre.

`motionDisabled()` honours both `prefers-reduced-motion` and the in-app setting,
and every helper degrades to an instant no-op.

## 8. Tooling and build

Rust and `wasm-pack` run **on the host**; node/npm run in **podman**.

```sh
rustup target add wasm32-unknown-unknown   # once
cd web
npm run build:wasm     # host: wasm-pack -> web/src/wasm/
./start.sh             # dev server on :5173
./start.sh preview     # production build on :4173
./start.sh build       # build only
./npm.sh <args>        # arbitrary npm command in a container
```

- Image `docker.io/library/node:24-alpine`; `node_modules` lives in the named
  volume `bea-web-node-modules` because bind-mounted `node_modules` is slow on
  macOS and loses ownership through virtiofs.
- `start.sh` force-removes a stale `bea-web-server` container first — closing the
  terminal does not always stop it, and it keeps holding the port.
- `web/src/wasm/` is generated and gitignored, so `build:wasm` must run before
  `npm run build` on a fresh clone.

CI: `.github/workflows/pages.yml` adds the wasm target, installs `wasm-pack`,
runs `cargo test`, `npm ci`, `build:wasm`, `test:engine`, `npm test`, `npm run
build`, then uploads `web/dist` and deploys. Only official `actions/*` are used.
Setting the repository variable `CUSTOM_DOMAIN` writes a `CNAME` into the
artifact; without it the project URL is used. Pages source must be set to
"GitHub Actions" in repository settings.

## 9. Gotchas worth knowing before changing anything

1. **serde-wasm-bindgen maps `None` to `undefined`.** Without
   `serialize_missing_as_null(true)` every `=== null` check in TS silently fails
   (`vlanTag`, `expectedPort`, `result`, …).
2. **CSS transform clobbers the SVG transform attribute.** Animating
   `transform` on a positioned SVG group without re-stating its `translate`
   snaps it to the origin — and with `fill: 'both'` it stays there.
3. **RFC 5952 never compresses a single zero group.** IPv6 abbreviation
   questions need a contiguous run of at least two zero groups, otherwise they
   are unanswerable. `random_ipv6_subnet` takes a `zero_group_run` parameter.
4. **`/31` and `/32` routes can never match** in `route_for`, because the
   destination equals the network address. Inherited behaviour; the generator
   never produces those masks.
5. **Reflection is impossible in wasm** — hence the static quiz `REGISTRY`.
6. **wasm-pack ships an older `wasm-opt`** than the features rustc emits by
   default. `wasm-api/Cargo.toml` passes `--enable-bulk-memory`,
   `--enable-sign-ext`, `--enable-nontrapping-float-to-int`,
   `--enable-mutable-globals`, `--enable-reference-types`, `--enable-multivalue`.
   Without them the build fails with a wasm-validator error.
7. **Node 24 makes `globalThis.navigator` getter-only**; test shims must not
   assign to it.
8. **`npm ci` fails on any package.json/lockfile version drift** — always bump
   with `npm version`.
9. **Grid `align-items: stretch`** was making every card on the home page grow
   when one card's options expanded; `align-items: start` is required.
10. **The root `.gitignore` is the VisualStudio one.** It ignores `[Dd]ebug/` and
    `[Rr]elease/` but not `target/`, so `engine/.gitignore` is what actually
    keeps Rust build output out of the repo.
11. **`shared/config.ts` must not touch `window` at module load.** It is pulled
    in by `animate.ts`, which the vitest suites import against a partial DOM
    shim. The query string is therefore read lazily and inside a `try`.

## 10. Deliberate non-goals

- No certificates, no encryption, no submission, no accounts, no analytics.
- No runtime network calls whatsoever.
- The WPF projects are never modified.
- Not a pixel-for-pixel recreation of the desktop UI.
- Rust→wasm is deterrence against casual answer-hunting, not real DRM.
- IE and other pre-wasm browsers are unsupported (WASM + ES2022 baseline).
